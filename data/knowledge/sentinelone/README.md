# SentinelOne knowledge artifacts

Grounded world model for the connected SentinelOne tenant, built per `Sentry_AgenticSOC_Build_Brief_for_Claude.md`. Everything here is derived from live tool calls against the tenant, never invented. Layout:

| Path | Populated by | Contents |
|---|---|---|
| `mcp_tools.md` | Milestone 0 (this pass) | Full inventory of the 33 tools the `sentinelone` MCP server exposes, with real parameter schemas and verified/unverified status per tool. |
| `environment_map.yaml` | Milestone 1 (populated) | What exists in the tenant: hierarchy, endpoints, policies, alerts/storylines, vulnerabilities/applications, optional modules, the Deep Visibility profile, enums, and the tool used per item. Generated by `scripts/discover_sentinelone_environment.py` (`python scripts/discover_sentinelone_environment.py --confirm-dv`, rerunnable). Two real gaps found and recorded honestly rather than fabricated: this tenant's `sentinelone` MCP server has no dedicated tool for endpoint-protection policies at all, and no distinct "Threats" tool (threat questions route to Alerts — see `mcp_tools.md`). |
| `ontology/` | Milestone 2 (populated, draft pending review) | 10 entities, real attributes (with population noted), relationships as edges, decoded enums, lifecycle states, per-entity tool bindings — generated by `scripts/build_sentinelone_ontology.py`. Carries `status: draft_pending_review`; see `ontology/README.md`. |
| `coverage_matrix/` | Milestone 3 (populated, draft pending review) | 12 rows: question class, example, target entity, source module, retrieval path, MITRE technique, expected result shape, priority, status, forbidden source. Gap-closing set flagged (`threat_count`, `host_lookup`, `storyline_pivot`, `agent_health`, `cve_traversal`). Doubles as the Milestone 8 test set; see `coverage_matrix/README.md`. |
| `recipes/` | Milestone 4 (populated) | 7 recipes (all 5 gap-closing + `threat_detail` + `vulnerability_general`), each live-validated against the tenant and tagged `stable`. Real edge cases captured (empty result, pagination); throttle/permission/retention edge cases deliberately not forced. See `recipes/README.md`. |
| `dv_cookbook/` | Milestone 5 (populated) | Field dictionary (4 of 6 categories confirmed real fields) and 6 MITRE-tagged hunt templates, all `experimental` since `purple_ai()` failed systemically this session (confirmed via diagnostic probe, not fixable from this side) — hand-composed instead, per explicit direction. `recipes/storyline_pivot.yaml` extended with a live-confirmed Deep Visibility sweep stage. See `dv_cookbook/README.md`. |

Each subdirectory is currently empty except for this README — populated milestone by milestone, each requiring its own acceptance check before starting, per the build brief's sequencing rule. Do not hand-author content into these directories ahead of the milestone that's supposed to generate it from real tenant data.
